# Tesla BLE 仪表微信小程序 — 开发计划

> 版本：v1.0（2026-11-25）
> 参考项目：`ESP32-S3-ROUND-DISPLAY`（ESP32-S3 圆屏仪表）+ `TeslaBleBackend`（BLE/协议后端库）
> 小程序项目目录：`tesla-miniapp/`（本文件所在目录，代码后续全部建在此目录下）

---

## 1. 目标与范围

用微信小程序替代 ESP32 圆屏硬件，作为 **BLE 中心设备（Central/Client）** 直连车端（真车或
`simulator/sim_server.py` 模拟器），完整复刻 `ESP32-S3-ROUND-DISPLAY` 的仪表能力：

| 能力 | 说明 |
| --- | --- |
| BLE 连接 | 按 VIN 推导广播名精确扫描 → 连接 → 订阅通知，断线自动重连 |
| 加密握手 | ECDH P-256 握手 + AES-GCM 会话，握手成功前不解析任何业务帧 |
| 实时数据 | GetVehicleData 轮询（Drive / Charge / Climate / TirePressure 等类别） |
| 旁路数据 | 53 字节 `SimPayload` 遥测帧（模拟器非加密模式） |
| 仪表 UI | 行驶页 / 充电页 / 链路状态页 / 配钥页 / 门状态页，设计语言沿用圆屏设计稿 |
| 配钥 | add-key-request 明文配钥 + 状态轮询（贴卡确认） |

**不在本期范围**：车辆控制指令下发（Write 通道控制类命令）、多车管理、云端后台。

## 2. 角色与可行性

```
┌──────────────────┐   BLE (GATT)   ┌──────────────────────────┐
│ 微信小程序         │ ─────────────► │ 车端 / 模拟器 sim_server.py │
│ Central / Client  │ ◄───────────── │ Peripheral / Server       │
│ 读 Notify 0213    │   Notify 推送  │ Service 0211              │
│ 写 Write  0212    │                │ (写=0212 通知=0213)        │
└──────────────────┘                └──────────────────────────┘
```

与 `ESP32-S3-ROUND-DISPLAY` 完全同构：小程序 = ESP32 仪表的角色，只做客户端。

### 2.1 微信小程序 BLE 能力核对

| 需求 | 小程序 API | 结论 |
| --- | --- | --- |
| 打开蓝牙适配器 | `wx.openBluetoothAdapter` | ✅ |
| 扫描 + 按名称过滤 | `wx.startBluetoothDevicesDiscovery` + `onBluetoothDeviceFound`（本地按广播名精确匹配） | ✅ |
| 连接 / 断连 / 状态监听 | `wx.createBLEConnection` / `wx.closeBLEConnection` / `wx.onBLEConnectionStateChange` | ✅ |
| 服务/特征发现 | `wx.getBLEDeviceServices` / `wx.getBLEDeviceCharacteristics` | ✅ |
| 订阅通知 | `wx.notifyBLECharacteristicValueChange` + `wx.onBLECharacteristicValueChange` | ✅ |
| 写特征值（带响应） | `wx.writeBLECharacteristicValue`，**必须 `writeType: 'write'`** | ✅ ⚠️ 需显式指定 |
| MTU 协商 | `wx.setBLEMTU`（Android 支持，iOS 系统自动协商不可设） | ⚠️ 需兼容逻辑 |
| 分片收帧 | 通知回调按块到达，上层自行组帧 | ✅ 自实现 |

### 2.2 关键技术风险与对策

| 风险 | 说明 | 对策 |
| --- | --- | --- |
| 小程序无 WebCrypto / Node crypto | 逻辑层 JS 无原生加密能力 | 使用纯 JS 库：`@noble/curves`（P-256 ECDH）、`@noble/hashes`（sha1/sha256/hmac）、AES-GCM 选用纯 JS 实现（`@noble/ciphers`）；M1 阶段先做 npm 构建验证 |
| MTU 限制 | 默认写 20 字节/包 | 发送按 `MTU-3` 分片（与 ESP32 端相同教训）；`setBLEMTU(247)` 失败时回退 20 字节分片 |
| iOS / Android 差异 | iOS MTU 由系统协商（通常 185+），Android 需手动 setMTU；`writeType` 支持度不同 | 封装 `BleLink` 层抹平；真机双端各测一轮 |
| npm 包体积 / 构建兼容 | @noble 系列均为 ESM | 开发者工具「构建 npm」+ 必要时 esbuild 预打包为 CJS |
| 蓝牙权限 | 需要定位/蓝牙权限弹窗（Android） | 首次进入引导授权，失败降级提示 |

## 3. 协议要点（移植自 TeslaBleBackend，硬约束）

以下规则与 ESP32 端完全一致，**必须遵守**：

1. **UUID**（协议固定值）
   - Service：`00000211-b2d1-43f0-9b88-960cebf8b91e`
   - Write（小程序 → 车）：`00000212-b2d1-43f0-9b88-960cebf8b91e`
   - Notify（车 → 小程序）：`00000213-b2d1-43f0-9b88-960cebf8b91e`
2. **广播名**：`S + sha1(VIN) 十六进制前16位 + C`（扫描按名称**精确匹配**）
3. **握手前置**（硬约束）：握手成功前**丢弃所有非握手帧**，不发送任何业务指令；
   UI 按"无数据"降级渲染（`--`），禁止展示业务数据
4. **加密模式帧分流**：先匹配 53 字节旁路帧；其余按 2 字节大端长度前缀处理加密帧
   （`declared + 2 == 已收字节数` 自洽即视为加密帧）；**加密模式下未握手时旁路帧直接丢弃**
5. **53B SimPayload**（小端序，仅非加密模式生效）：
   `speed_kmh f32 / motor_power_kw f32 / battery_level i32 / battery_range_km f32 / gear c1 /
   doors[6] u8 / locked u8 / charging u8 / charge_power_kw f32 / inside_temp f32 /
   outside_temp f32 / tpms[4] f32`
6. **写特征值必须带响应**（Write With Response），禁止无响应写
7. **轮询串行化**：上一条加密命令回包/超时前不发下一条（避免响应认证失败 fault=5）
8. **配钥流程**：add-key-request 为**明文**数据报直接发送；8s 重发间隔、最多 3 次，
   之后静默等待 90s 超时；车端回 WAIT 后**停止所有握手与配钥重发**，等待刷卡
9. **客户端私钥**：固定 32 字节 ECDSA P-256 私钥（与模拟器 `run.bat --client-pub` 白名单
   匹配），公钥为 65 字节非压缩格式（0x04 + X + Y）；私钥放在小程序**不提交 git** 的
   配置文件中（`config/secret.js`，加入 `.gitignore`），缺省回退内置测试密钥

## 4. 系统架构（分层映射）

与 ESP32 端同构，逐层移植：

```
ESP32-S3-ROUND-DISPLAY                     tesla-miniapp
──────────────────────                     ──────────────────────
BleLink (NimBLE)            ─────►         core/bleLink.js (wx.* API)
TeslaClient (握手/组帧/轮询) ─────►         core/teslaClient.js
TeslaCrypto (ECDH/AES-GCM)  ─────►         core/crypto/*.js (@noble 纯 JS)
PbCodec (protobuf)          ─────►         core/pbCodec.js
VehicleState / SourceStatus ─────►         core/vehicleState.js（JS 快照 + 订阅）
TeslaUiSource → UiModel     ─────►         core/uiModel.js
Dashboard (LVGL 页面)       ─────►         pages/dashboard/*（WXML + WXSS 横屏驾驶舱）
```

数据流：

```
onBLECharacteristicValueChange(0213)
        │ ArrayBuffer 原始字节
        ▼
FrameParser ──► 53B 旁路帧 / 长度前缀加密帧（跨通知边界组帧）
        │
        ▼
TeslaClient（状态机：Idle→Scanning→Connecting→Syncing→Ready→Reconnecting）
        │  写 vehicleState 快照，通知订阅者
        ▼
pages/dashboard（定时刷新数据模型并更新 WXML；数据过期时显示 `--`）
```

UI 页面状态机（沿用设计稿优先级）：

```
配钥页（phase != Idle 且链路 Ready，最高优先级）
  > 链路状态页（SCANNING / CONNECTING / SYNCING / RECONNECTING / ERROR）
  > charging == true → 充电页
  > charging == false → 行驶页
门状态页：链路 Ready 且任一门/前备箱/后备箱打开时叠加显示，全部关闭自动返回
```

## 6. UI 设计约定

设计语言完全沿用 `ESP32-S3-ROUND-DISPLAY/design/UI-DESIGN.md`，做手机屏适配：

- **适配策略**：手机横屏使用响应式驾驶舱布局；中央为速度环和挡位，左侧展示车辆俯视图，
  右侧展示胎压和锁状态，底部显示电量与预估续航。尺寸随屏幕宽高收缩，内容保持在一屏内。
- **颜色 token**（照抄设计稿）：

| Token | HEX | 用途 |
| --- | --- | --- |
| SCREEN | `#05070B` | 深色驾驶舱底色 |
| TEXT / DIM / FAINT | `#F5F7FB` / `#868C96` / `#626B78` | 数值 / 单位 / 标签 |
| TRACK | `#292B31` | 电量轨道 |
| GAUGE_CYAN | `#A9EAFF` | 仪表冷色高光 |
| TESLA_RED | `#E82127` | 速度环高段、正功率、告警 |
| REGEN_GREEN | `#21C15E` | 能量回收、充电环 |
| CAUTION | `#FFB340` | 中高段、续航、扫描/配钥 |
| ALERT | `#FF453A` | 断连、胎压异常、车门开启 |

- **速度环配色**：深色内圈搭配金属蓝灰渐层外环；胎压不足和车门状态仍使用告警色提示。
- **降级规则**：未握手时显示 `--`；行驶数据 3s 未更新则过期，辅助数据超过有效期（`AUX_DATA_STALE_MS`，约 126s）判定过期。
- 界面文案保持英文（与固件一致），日志中文。

## 8. 测试与联调方案

| 场景 | 步骤 | 预期 |
| --- | --- | --- |
| 旁路数据 | 启动 `python sim_server.py`（默认 VIN），小程序输入同 VIN 扫描连接 | 行驶页实时速度/SOC，3s 断流显示 `--` |

- 小程序侧：设置页内的连接事件日志（收发字节计数、状态迁移、fault 码），`vConsole`

## 9. 风险清单

| # | 风险 | 影响 | 缓解 |
| --- | --- | --- | --- |
| 1 | 纯 JS AES-GCM 性能不足（每帧加解密） | 数据延迟 | 帧很小（<250B），实测若慢再换 WASM 方案 |
| 2 | iOS 固定 MTU 导致长加密帧分片错乱 | 解析失败 | 组帧缓冲 + 长度自洽校验已覆盖；限制 `CFG_TESLA_MAX_FRAME` 一致 |
| 3 | 微信后台限制 BLE 10s 空闲断开 | 切后台丢连接 | `onHide` 提示用户保持前台；重连机制兜底 |
| 4 | protobuf 字段遗漏 | 响应解析失败 | 对照 `TeslaBleBackend/src/tesla/PbCodec.h` 与 `simulator/tesla_protocol/` 的 .proto |
| 5 | `writeType: 'write'` 在部分安卓 ROM 被忽略 | 写入失败 | 写入后校验失败码，回退基础写法并记录日志 |

## 11. 实施约定

- 代码由 AI 按里程碑逐个实现；**每完成一个里程碑先自述改动与验证要点，由用户在
  微信开发者工具中自行预览验证后再进入下一里程碑**（沿用"编译/烧录由用户处理"的约定）。
- 提交粒度按里程碑；`config/secret.js`（真实私钥）一律不入库。
- 模拟器联调前先结束占用 BLE 广播句柄的旧模拟器进程（历史踩坑）。
