# 新电脑开发环境准备清单

本文按仓库当前配置整理，面向 Windows 10/11。仓库包含主仪表固件、ESP32-S3 圆屏固件、BLE 仿真器和可复用 BLE 后端；请按实际要开发的部分安装对应环境。

## 1. 必需的电脑环境

- [ ] Windows 10/11 电脑，建议使用 64 位系统。
- [ ] 安装 Visual Studio Code。
- [ ] 安装 VS Code 扩展 **PlatformIO IDE**（扩展 ID：`platformio.platformio-ide`）。这是主固件工程当前明确推荐的扩展。
- [ ] 准备可传数据的 USB 线，以及目标 ESP32 开发板。
- [ ] 首次构建时保持网络连接。PlatformIO 会自动下载 ESP32 平台、编译工具链和 `platformio.ini` 声明的库；不需要单独安装 Arduino IDE 或 ESP-IDF。

VS Code 中的 Python 扩展可用于编辑/调试仿真器，但不是固件编译的必需项。当前固件使用 Arduino 框架，不需要为本项目安装 ESP-IDF 工具链。

### 当前电脑的 VS Code 扩展（迁移参考）

当前电脑检测到以下已安装扩展；工程内 `.vscode\extensions.json` 明确推荐的只有 PlatformIO IDE：

| 扩展 | 用途/新电脑是否需要 |
| --- | --- |
| `platformio.platformio-ide` | **需要**：主仪表与 S3 固件构建、烧录、串口监视 |
| `ms-python.python`、`ms-python.vscode-python-envs`、`ms-python.debugpy`、`ms-python.vscode-pylance` | Python 仿真器开发/调试时安装 |
| `ms-vscode.cpptools`、`ms-vscode.cpp-devtools`、`ms-vscode.cpptools-themes`、`ms-vscode.cpptools-extension-pack` | C/C++ 编辑辅助；可选。工程配置未要求安装，其中 extension pack 还列在不推荐项中 |
| `ms-vscode.cmake-tools` | 本仓库 PlatformIO Arduino 构建不需要 |
| `octref.vetur` | 本仓库不需要（当前代码没有由此扩展支持的 Vue 工程配置） |
| `ms-ceintl.vscode-language-pack-zh-hans` | 中文界面偏好，可选 |

扩展列表是当前电脑的检测结果，不代表每个扩展都是此项目的依赖。

## 2. 获取并打开整个仓库

必须克隆整个仓库，不能只拷贝 `TESLA-DASHBOARD` 子目录：主工程通过 `lib_extra_dirs = ..` 引用仓库根目录下的 `TeslaBleBackend`。

```powershell
git clone https://github.com/jeefgit/Tesla-BLE-Simulator.git
```

在 VS Code 中打开 `Tesla-BLE-Simulator\TESLA-DASHBOARD` 文件夹进行主仪表开发。不要把 `.pio` 构建缓存当作环境依赖；新电脑首次构建会重新生成它。

## 3. 主仪表固件：ESP32 Dev Module

`TESLA-DASHBOARD\platformio.ini` 当前默认环境为 `esp32dev`：

- 板型：`esp32dev`（ESP32 Dev Module）
- 框架：Arduino
- 串口监视器波特率：115200
- 上传波特率：921600
- PlatformIO 库依赖：NimBLE-Arduino 2.x（配置范围从 2.5.1 起）、LVGL 9、LovyanGFX 1.x

以上 PlatformIO 依赖会由工程自动解析和下载，不要手动复制旧电脑的 `.pio` 目录。README 记录的已验证基线为 PlatformIO Core 6.2.0、Espressif32 8.0.0、Arduino core 3.3.12；工程配置没有固定这些平台版本，实际版本以新电脑首次解析结果为准。NimBLE-Arduino 必须使用 2.x。

打开 VS Code 的 PlatformIO 终端，在 `TESLA-DASHBOARD` 目录运行：

```powershell
pio run
pio run -t upload
pio device monitor -b 115200
```

也可以使用 VS Code 中 PlatformIO 的 Build、Upload、Monitor 按钮。上传前在设备管理器确认开发板对应的 COM 端口；如果自动识别失败，再在 PlatformIO 设置中选择正确串口。

## 4. USB 串口驱动与可选调试器

- **串口驱动（烧录必需）**：由开发板上的 USB-UART 芯片决定，常见为 Silicon Labs CP210x 或 WCH CH340。插板后先看 Windows 设备管理器中的芯片/设备名称和 COM 端口，再按芯片型号安装官方驱动；不同板子不一定使用同一种驱动。
- **USB 数据线**：确认不是仅供电线。否则设备管理器中不会出现串口，PlatformIO 也无法上传。
- **硬件调试器（可选）**：仅在需要断点/单步调试且开发板与调试接口匹配时准备；普通编译、串口烧录和运行不需要额外调试器。

当前电脑设备管理器可见 `USB-SERIAL CH340`（COM3/COM4/COM5）和 `USB 串行设备`（COM6）。这些是当前连接设备的快照，不是新电脑必须复刻的端口号；新电脑按实际设备名称和 COM 号配置即可。

## 5. BLE 仿真器（可选）

若要从电脑运行 `simulator` 中的 Python BLE 仿真器，建议安装 **Python 3.12（64 位）**，并确保 `py` / `python` 命令可用。模拟器 README 标注 Python 3.10+；仓库对 Python 3.12+ 的依赖处理包含在项目自身的 `vendor` 目录中。

在 `simulator` 目录运行：

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
python sim_server.py
```

仿真器主要依赖 `bless`、`protobuf` 和 `cryptography`。也可按 `simulator\README.md` 使用 `run.bat`；该脚本会安装依赖并请求管理员权限。若使用虚拟环境，推荐在已激活的环境中按上面的命令运行。

### 可选：CSR8510 USB 蓝牙适配器 + WinUSB

只有要用 Bumble 通过 USB HCI 直接控制蓝牙适配器、进行硬件广播仿真时，才需要额外准备独立 USB 蓝牙适配器（项目文档推荐 CSR8510 A10）并使用 Zadig 将**该适配器**配置为 WinUSB。它不是 PlatformIO 编译、ESP32 烧录或普通开发所需驱动。

驱动替换会改变该适配器在 Windows 中的用途。务必在 Zadig 中核对设备名称/USB ID，**不要**替换电脑内置蓝牙、键盘、鼠标或其他 USB 设备的驱动。具体操作和恢复方法见 `simulator\docs\USB_BLUETOOTH_DONGLE_SETUP.md`。

## 6. ESP32-S3 圆屏固件（可选）

只有开发 Waveshare ESP32-S3-Touch-AMOLED-1.75-B 圆屏时才需要此工程。在 VS Code 打开 `ESP32-S3-ROUND-DISPLAY`，其 PlatformIO 环境为 `waveshare_esp32_s3`，使用 `esp32-s3-devkitc-1` 板型、Arduino 框架和 16 MB Flash 配置。PlatformIO 会自动安装该工程声明的 NimBLE-Arduino、LVGL 及 Arduino_GFX 库。

```powershell
pio run
pio run -t upload
pio device monitor -b 115200
```

该圆屏工程与主仪表工程是独立的，主仪表使用的开发板、屏幕和固件环境不能代替它。

## 7. 换电脑后需要检查的本机设置

- `.vscode\settings.json` 中有旧电脑的 ESP-IDF 路径和 `COM3` 串口设置。当前 Arduino 工程不依赖该 ESP-IDF 路径；实际 COM 号应以新电脑设备管理器显示为准。
- `.vscode\launch.json` 中的 ELF 文件路径和 Xtensa 工具链目录包含旧电脑的绝对路径。普通编译/烧录不受影响；需要调试时用 PlatformIO 在新电脑重新生成/配置调试项，或改成新电脑上的实际路径。
- 如使用真车/已配对 BLE 身份，旧电脑可能有本地密钥文件 `include\secrets\tesla_client_key.h`。按需通过安全方式单独迁移，不要提交到 Git；没有该文件仍可使用项目配置中的默认测试密钥进行相应开发。
- 模拟器 VIN 与固件 `include\config.h` 中的 `CFG_TESLA_VIN` 必须一致；使用不同 VIN 时同步修改两处。

## 8. 搭建完成后的检查

- [ ] VS Code 能打开 `TESLA-DASHBOARD`，PlatformIO 成功识别 `esp32dev` 环境。
- [ ] `pio run` 编译成功。
- [ ] 开发板连接后设备管理器出现对应 COM 端口，`pio run -t upload` 可完成烧录。
- [ ] `pio device monitor -b 115200` 能看到串口输出。
- [ ] 如需端到端 BLE 联调，Python 仿真器能启动，且仿真器 VIN 与固件配置一致。
- [ ] 如需 USB HCI 广播，再按专门指南配置 CSR8510/WinUSB。
